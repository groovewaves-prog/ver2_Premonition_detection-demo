## Slide 2 — なぜ従来型監視では間に合わないのか（Alert Fatigue のジレンマ）

■ 用語メモ
- **Alert Fatigue（アラート疲れ）**: 通知が多すぎて本当に重要な警告が埋もれる現象
- **偽陽性 / False Positive**: 実際は異常でないのに異常とみなしてしまう誤検知

■ ジレンマの構造
| 設定 | 結果 |
|---|---|
| 閾値を厳しく | 偽陽性が 1 日数百〜数千件 → 運用麻痺 |
| 閾値を緩く | 数日〜数週かけて進行する「緩やかな劣化」を見逃す |

■ 根本原因
従来ツールは各機器を **独立した点** として監視している。実際のネットワークは
**接続された網（グラフ）** であり、故障は単独ではなく「隣接機器との相関」を通じて現れる。

■ 本ツールの解決アプローチ
機器の接続関係を地図として保持し、「この機器が劣化すると、どの機器にどのくらいの時間で連鎖するか」
を**数時間前に**予測する。誤報を減らすのではなく、構造的に「真に重要な予兆だけ」を届ける。

## Slide 3 — 予兆検知パイプライン全体像（9 レイヤー）

■ 用語メモ
- **BFS**: 幅優先探索。トポロジー上で「近い順」に影響範囲をたどるアルゴリズム
- **RUL (Remaining Useful Life)**: 残存寿命。「あと何時間／何日使えるか」の推定値
- **Confidence (信頼度)**: 予兆の確からしさ。本ツールは 0.40 を発報閾値とする

■ パイプライン（WARNING アラーム受信から予兆発報まで）
```
WARNING アラーム
    │
    ├─ [L6] Sentence Transformer: エスカレーションルールとの意味的照合
    ├─ [L4] 線形回帰: メトリクストレンドから RUL（残存寿命）推定
    ├─ [L7] BFS: 下流影響範囲の算出
    │
    ├─ [L1] ChiGAD + HeteroGNN: スペクトル異常検知
    ├─ [L2] GDN: 正常状態からの偏差検知
    ├─ [L3] GrayScope + Granger: メトリクス因果推論（暗黙的障害）
    │
    ├─ [L5] ベイズ推論: 事後確率で信頼度統合
    ├─ [L8] 2 エージェント交差検証: 偽陽性フィルタ
    │
    └─ 予兆発報（confidence ≥ 0.40）
         └─ [L9] ダッシュボード可視化
```

■ ポイント
- 9 レイヤーすべてを通すのではなく、**並列 + 段階的フィルタ**の構造
- 最後の交差検証（L8）は「2 人のアナリストが合意したら発報」する多エージェント設計

出典: CLAUDE.md「予兆検知アルゴリズム パイプライン全体像」

## Slide 4 — 技術① GNN（ネットワーク地図の読取り）

■ 用語メモ
- **GNN (Graph Neural Network)**: 機器の接続関係（グラフ）をそのまま入力として扱える深層学習モデル
- **ChiGAD**: カイ二乗ウェーブレットフィルタを備えた GNN（KDD 2025, Li et al.）
- **GDN (Graph Deviation Network)**: 正常時の相関パターンからの逸脱を検知する GNN（AAAI 2021, Deng & Hooi）
- **ウェーブレットフィルタ**: 信号を「周波数帯域ごと」に分解する数学的フィルタ

■ 実証数値
- **Precision 99%**（Deng & Hooi, AAAI 2021 / SWaT データセット）
- F1 スコアで競合手法を **+54%** 上回る

■ 比喩
心電図を単独で見るのではなく、**心臓・肺・血圧・体温の相関関係がいつもと違う**ことを
検知するイメージ。1 台の機器より、周辺機器との「相関パターンが崩れた瞬間」を捉える方が
早く正確。

■ 運用上の意味
- カスケード障害（ドミノ倒し）の数時間前予測が可能
- HA 構成（冗長・バックアップあり）を理解し、バックアップ稼働中の誤アラートを出さない
- ChiGAD のウェーブレットが **高周波の異常信号**（標準 GNN が取りこぼす情報）を保持するため、
  早期の微小変化も拾える

## Slide 5 — 技術② PHM（故障までの残り時間の推定）

■ 用語メモ
- **PHM (Prognostics and Health Management)**: 設備が「あと何時間使えるか」を推定する工学分野。製造業で発達
- **1DCNN-BiLSTM**: 1 次元畳み込み + 双方向 LSTM。時系列パターンから未来値を推定するモデル構造
- **SFP**: 光ファイバーの送受信モジュール（光トランシーバー）。消耗品で劣化しやすい

■ 実証数値
- **テスト精度 97.2%**（Ahn et al., Sensors / MDPI 2023, FlexCFL-1DCNN-BiLSTM 構成）
- 分散拠点で**生データを共有せず**に達成（連合学習との統合）

■ 比喩
飛行機エンジンの計画保全は「何時間飛んだら交換」と決まっているが、実際の劣化速度は個体差が大きい。
PHM は**実際の劣化波形**から「この個体はあと何時間か」を推定する。

■ 運用上の意味
- 「このSFP は推定 68 時間後に限界値を超えます」と可視化できる
- **突発対応（緊急出動・残業・緊急調達）→ 計画対応（週末メンテ窓で交換）** にコスト構造が変わる
- 本ツールでは線形回帰による簡易 TTF 推定（CLAUDE.md の L4）から、Phase 3 で 1DCNN-BiLSTM 実装に拡張する設計

## Slide 6 — 技術③④ ベイズ推論 ＋ LLM（自己学習と手順自動生成）

■ 用語メモ
- **ベイズ推論**: 新しい証拠が増えるたびに確率を更新する数学的手法。式: `P(障害|症状) = P(症状|障害) × P(障害) / P(症状)`
- **LLM (Large Language Model)**: 大規模言語モデル。ChatGPT などで知られる
- **RAG (Retrieval-Augmented Generation)**: LLM が回答前に信頼できる資料を参照させる仕組み
- **ハルシネーション**: LLM が実在しない事実を「もっともらしく」生成する問題

■ 技術③ ベイズ推論（自己学習）
- 過去 168 時間（7 日間）の履歴から事後確率を更新
- 「このアラートパターンは過去に実障害につながったか、空振りだったか」を実績で学習
- 時系列パターン強化（`_calculate_temporal_boost`）で周期性も加味
- 運用上の意味: **導入後に使い込むほど精度が上がる**。AI 導入後の「全然当たらない」期間を設計で排除

■ 技術④ LLM（手順書生成）
- LLM は**限定使用**: 前段の L1–L3 が「真の危機」と確定した場合のみ呼び出す
- 回答生成前に必ず「過去の実解決事例 DB」を参照させる（RAG / Trustworthy GNN+LLM, arXiv 2502.08353）
- 運用上の意味: **熟練エンジニアの暗黙知がツールに蓄積**される。「何をすべきか」を人間が考える時間を削減

## Slide 7 — 技術⑤ 導入初日から動く仕組み（コールドスタート解消）

■ 用語メモ
- **コールドスタート問題**: AI 導入直後、学習データが不足して機能しない期間
- **ホワイトボックス GNN**: 判断根拠を人間が確認できる説明可能な GNN
- **知識蒸留**: 既存モデル（ここでは LLM）から別モデル（ここでは GNN）へ知識を移す技術

■ 一般的な AI ツールの問題
典型的な GNN ツールは正常データ蓄積に **3〜6 ヶ月** を要する。この期間は「見ているだけ」で予兆検知できない。

■ 本ツールの 2 つの解決策

**解決策 1: ホワイトボックス GNN（ChiGAD / KDD 2025）**
- 各機器の異常スコアを「どのセンサー間の相関が崩れたか」に分解・表示
- トポロジー情報（接続構造）だけから初日に相関パターンを推定 → 初日から検知可能
- 担当者が「なぜ危険と判断したか」を画面で確認 → 誤判定を即補正できる

**解決策 2: LLM による疑似正常データ生成（arXiv 2502.08353 / 2025）**
- LLM が `topology.json` から「Cisco ISR ルーターなら CPU / インターフェースはどの分布か」を推論
- この**疑似正常データ**を GNN の初期学習に使う
- 実データが蓄積されるにつれ自然に精度が向上する

経営上の意味: **「導入して半年は様子見」が不要。投資対効果の測定を早期に開始できる。**

## Slide 8 — 補完設計とセキュリティ 3 層

■ 用語メモ
- **連合学習 (Federated Learning / FL)**: 生データを共有せず、モデルの学習結果（重み）だけを持ち寄る協調学習方式
- **マスキング**: 機密情報（IP アドレス等）を送信前に置換・除去する処理

■ 5 技術が「弱点を補い合う」設計

| 技術 | 単体の弱点 | 誰が補うか |
|---|---|---|
| ① ルールベース | 未知事象を見逃す | GNN + ベイズ |
| ② GNN | 時系列の文脈が読めない | ベイズ + LLM 知識蒸留 |
| ③ ベイズ推論 | 初期データがないと精度が出ない | GNN + LLM 疑似データ |
| ④ PHM | 単拠点では過学習しやすい | 連合学習 |
| ⑤ LLM | ハルシネーション・コスト高 | 前段 3 技術 + RAG |

ポイント: 「精度が高い」ではなく「**間違いにくい**」設計を優先。工学の「冗長性」と同じ発想。

■ セキュリティ 3 層
1. **機密情報マスキング**: 外部 AI API 送信前に IP / MAC / ホスト名 / VLAN ID を自動除去（コードレベルで強制）
2. **連合学習でデータを持ち出さない**: モデル重みだけを共有、生データは拠点外に出ない（Frontiers AI 2025 設計）
3. **ホワイトボックス推論**: 「光信号の劣化パターンが過去事例と 87% 一致、配下 32 台に 4 時間以内に影響する確率 91%」
   のように根拠を開示。担当者が覆せる

## Slide 9 — 段階導入 Phase 1–5 と期待効果

■ 用語メモ
- **RUL ゲージ**: 残存寿命を可視化した UI コンポーネント
- **メンテカレンダー**: 予測された故障時期を基にした計画保全スケジュール

■ 5 段階導入

| Phase | 期間 | 得られる価値 |
|---|---|---|
| Phase 1-2 基盤安定化 + ベイズ補強 | 即日〜数週間 | 誤アラート大幅削減・検知精度向上 |
| Phase 3 PHM 層実装 | 1〜2 ヶ月 | SFP など消耗品の残存寿命可視化 |
| Phase 4 UI・ダッシュボード | 2〜3 ヶ月 | 経営層向けのリスク可視化画面完成 |
| Phase 5 連合学習 | 運用しながら | 全拠点の知識共有で継続的な精度向上 |

設計思想: **各フェーズが独立して価値を持つ**。Phase 1 完了時点で継続判断、Phase 3 完了時点で ROI 判断が可能。

■ 期待効果（業界平均値と本ツール設計方向性からの推定）
- **▲80%** 誤アラート（偽陽性）削減
- **数時間前** 障害発生前の事前検知
- **突発対応 → 計画保全** への行動パターン転換

■ コスト構造の転換
| 項目 | 現状 | 導入後 |
|---|---|---|
| 障害発見 | 発生後（サービス停止先行） | 数時間前（サービス継続したまま） |
| 担当者行動 | 深夜・休日の緊急対応 | 定時内の計画対応 |
| 部品調達 | 緊急調達（高コスト） | 計画調達（通常価格） |
| 影響範囲 | 連鎖してから気付く | 事前に可視化・局所化 |

## Slide 10 — まとめ / 参照論文 7 本

■ 本ツールで実現すること
1. **エンジニアが「追われる」から「制御する」立場へ**
   大量アラートの受け身処理から、重要な予兆に先手を打つ仕事へ
2. **「突発コスト」が「計画コスト」へ転換**
   緊急対応・深夜呼び出し・緊急調達は「予測できなかったことへの割増料金」
3. **根拠のある意思決定**
   「AI がそう言ったから」ではなく「この論文の 97.2% 精度のモデルが、過去類似事例と照合して判断した」

■ 設計根拠となった査読済み論文 7 本

|---|---|---|

## 付録 — 補足情報（スライドに入りきらなかった項目）

| カテゴリ | シナリオ |

| 複合 | WAN 複合障害（電源 & FAN）/ 同時多発（FW & AP） |

### 信頼度スコア計算式（参考）
```
confidence = base_confidence
           × (0.8 + 0.2 × match_quality)
           × (1.0 - REDUNDANCY_DISCOUNT)   # HA 構成時: 0.15
           × SPOF_BOOST                    # SPOF 時: 1.10
```
閾値: `EMBEDDING_THRESHOLD = 0.40`, `MIN_PREDICTION_CONFIDENCE = 0.40`

### ヒアリング項目（導入検討時）
1. 現在の突発障害対応コスト（残業・緊急手配・機会損失）は年間いくらか
2. エンジニアの何割がアラート確認・誤報処理に費やされているか
3. 熟練エンジニアの異動・退職時、知識は次の担当者に引き継げているか
